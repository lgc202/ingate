---
title: 运维助手
description: 配置模型连接，使用只读工具查询配置、分析流量并定位失败请求
---

运维助手面向 Ingate 管理员，把自然语言问题转换为对当前配置和观测数据的只读查询。它可以解释 Gateway、Route 与 Service 的关系，比较流量指标，并沿失败样本继续排查；不能创建、修改或删除任何资源。

Assistant 是可选的控制面组件，不参与配置发布或业务流量。Assistant、模型端点或会话存储不可用时，Console 的其他管理功能和 Envoy 转发不受影响。

## 使用前准备

开始前需要：

1. 一个支持工具调用的 OpenAI Chat Completions 兼容模型，或支持工具调用的 Anthropic Messages 模型
2. Assistant 容器可以访问的模型 API 根地址
3. 模型名，以及模型端点要求的 API Key

如果准备让助手经过 Ingate 调用模型，还要先完成[模型 Service 和 AI Route](../../getting-started/first-ai-route/)；受保护 Route 还需要一个已获授权的 Caller 密钥。运维助手是只读的，不能替你创建这些前置资源。

## 配置模型连接

进入 **工作台 → 运维助手**，选择右上角的 **模型设置**。连接方式有两种。

### 直连模型端点

Assistant 直接向模型服务发起请求：

| 配置 | 说明 |
| --- | --- |
| 接口协议 | `OpenAI 兼容` 或 `Anthropic` |
| 模型名称 | 模型端点实际接受的模型名 |
| 服务地址 | 模型 API 根地址，例如 `https://api.example.com/v1` |
| 访问密钥 | 模型端点不要求认证时可以留空 |
| 请求超时 | 单次模型请求的最长等待时间，范围为 1–1800 秒 |
| 最大输出 Token | 单次回答的最大输出量 |
| 思考预算 Token | 只在直连 Anthropic 时可用；设为 `0` 表示关闭 |

Anthropic 思考预算启用时至少为 1024，并且必须小于最大输出 Token。

### 通过当前网关

Assistant 使用 Ingate AI Route 作为模型入口：

| 配置 | 说明 |
| --- | --- |
| 接口协议 | 固定为 `OpenAI 兼容`，真实厂商协议由 AI Route 转换 |
| 模型名称 | AI Route 发布的客户端模型名 |
| 服务地址 | Assistant 可访问的数据面 API 根地址，例如 Compose 内的 `http://envoy:8080/v1` |
| 访问密钥 | 公开 Route 可留空；受保护 Route 填写已获授权的 Caller 密钥 |

这条路径会正常经过 Route 授权、请求限流、Token 额度和观测链路。Assistant 不保存 Route ID，也不会绕过数据面的治理规则。

:::caution
运维助手依赖模型工具调用。通过 Ingate 时，AI Route 当前必须使用 OpenAI 兼容模型 Service；现有 OpenAI-to-Anthropic 转换只覆盖文本对话和共有采样参数，不转换工具调用。
:::

API Key 只在服务端保存。重新打开设置时只显示“已配置”，不会回显原文；留空表示保留现有密钥，勾选“清除已保存的访问密钥”才会删除它。保存的新连接只影响之后开始的执行，不会切换正在运行的回答。

## 发起一次查询

1. 选择 **新建会话**。
2. 输入一个包含对象、时间范围和期望结果的问题。
3. 按 `Enter` 或选择 **发送**。
4. 在回答过程中查看模型调用和工具调用步骤；需要中止时选择 **停止回答**。

例如：

```text
比较最近 1 小时各路由的请求量和 5xx 比例，列出最异常的三条路由。
```

```text
检查订单路由的关联网关、服务、超时和重试配置，并结合最近失败请求说明可能原因。
```

```text
这条请求为什么因为 Token 额度被拒绝？请继续查询对应调用方的当前额度。
```

问题中给出明确时间范围和资源名称，通常能减少不必要的查询。助手会先使用汇总数据缩小范围，再按需读取配置或单条请求，不会批量读取所有请求详情。

## 当前只读工具

| 能力 | 用途 |
| --- | --- |
| 查询 Gateway、Route、Service | 按名称筛选资源并查看当前状态 |
| 查询 Route 关联配置 | 一次读取 Route、关联网关、目标 Service、超时和重试设置 |
| 分析流量 | 按 Gateway、Route 或 Service 比较请求量、服务端错误率和 P95 耗时 |
| 查询近期失败 | 在指定时间与资源范围内抽取 4xx、5xx 或无响应样本 |
| 查询请求详情 | 读取某条失败样本的耗时、流量大小、转发次数和可用的模型调用结果 |
| 查询 Caller Token 额度 | 在明确 Caller 后读取命中策略、已用额度、剩余额度和重置时间 |

工具不提供资源写入、Shell、数据库查询、任意 HTTP 请求或用户自定义 MCP 能力。模型只能调用 Assistant 注册的这组工具。

## 会话、执行与恢复

发送问题后，Assistant 会先持久化用户消息，再创建一个异步执行。Console 通过 SSE 展示实时内容和执行步骤：

- 刷新页面后，仍在运行的执行会从最后收到的事件继续订阅
- SSE 连接暂时中断时，Console 会读取持久状态并自动恢复
- 短期流事件过期后，仍可读取执行终态和最终回答，但不能重放逐段输出
- 同一会话同一时刻只运行一个回答；可以切换到其他会话查看历史内容
- 取消排队中或运行中的执行后，状态会收敛为“已取消”

会话支持重命名和删除。删除会话会同时删除该会话下的消息、执行和步骤，不影响 Ingate 资源或请求记录。

## 数据与安全边界

MySQL 保存模型连接、会话、用户问题、最终回答、模型明确返回的推理内容、执行状态和步骤摘要。Redis Stream 只保存 SSE 断线重连所需的短期事件。

模型会收到当前对话、Assistant 的系统指令、工具定义以及本次查询所需的工具结果。工具结果只包含诊断所需的产品字段，不包含 Service 凭据、证书私钥、访问密钥、请求 Header、查询参数或正文。完整工具参数、原始工具输出和完整模型请求不会写入执行步骤或应用日志。

如果模型端点由第三方运营，请按其数据处理政策评估是否允许发送管理员问题、资源名称和观测摘要。

## 常见问题

### 页面提示“尚未配置模型”

打开 **模型设置**，完整填写连接方式、服务地址和模型名称并保存。只创建 AI Route 不会自动配置 Assistant。

### 保存成功，但回答失败

依次确认：

1. 服务地址是模型 API 根地址，不带查询参数或 URL 片段
2. Assistant 容器能够解析并访问该地址
3. 模型名和 API Key 有效
4. 模型支持工具调用
5. 通过 Ingate 时，AI Route 已生效、目标是 OpenAI 兼容模型 Service、Caller 已获授权且额度未耗尽

失败步骤会保留稳定的错误类别和安全摘要；模型服务的内部响应正文不会直接展示给管理员。

### 实时回答中断

保持页面打开，Console 会自动从最后一个事件恢复。刷新页面也不会重新创建模型调用；如果执行已经结束，页面会从 MySQL 读取最终结果。

### 回答没有引用当前数据

明确指定资源、时间范围和希望比较的指标。如果模型没有使用工具，确认所选模型确实支持并启用了工具调用；Assistant 不会把模型自身知识当作 Ingate 当前状态的证据。

当前不提供写操作、变更审批、用户自定义 MCP 工具、多 Agent 委派、长期记忆或定时自动化。
