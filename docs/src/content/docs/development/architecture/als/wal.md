ALS 的 WAL 是 Kafka 故障期间的本地持久队列。正常直写不会先落 WAL；进入降级状态后，ALS 先追加待投递批次，Kafka 恢复后再从队首读取。只有 Kafka 确认成功，才截断已经提交的条目。

这里的“预写”是相对于降级批次的最终投递而言：先把尚未完成的投递意图写进可恢复日志，再执行 Kafka 重放并删除确认记录。它不是简单地把 protobuf 文件散落在目录里，也不意味着所有正常批次都要多写一次磁盘。

![ALS WAL 条目的编码、校验、追加和确认结构](/ingate/images/als/wal-entry.svg)

## WAL 代替普通文件

“直接写磁盘”仍要处理半次追加、文件顺序、确认位置、原子截断、重启校验和独占写入。WAL 把数据组织为单调递增的日志条目，并提供按索引读取与队首截断，减少自制存储协议的范围。

Ingate 使用 `tidwall/wal` 处理分段、索引、追加和截断；组件自己负责业务条目格式、CRC、容量、目录锁与恢复策略。使用库不等于把它当黑盒：持久性仍取决于 `NoSync` 配置、文件系统和底层设备。

## 条目格式

一个 Envoy 有效批次编码为一个 `QueueEntry`：

| 字段 | 用途 |
| --- | --- |
| `format_version` | 拒绝未知或旧格式，防止误读 |
| `enqueued_at_unix_nano` | 计算最老积压年龄 |
| `records` | 原始 `RequestRecord` protobuf 列表 |
| `traceparent` / `tracestate` | 回放 Trace 链接到原接收批次 |
| `crc32c` | 检测 Ingate 条目内容损坏 |

CRC 输入使用确定性 protobuf 编码，并把校验字段清零后计算。CRC32C 用于发现意外损坏，不是防篡改签名。能够修改 WAL 文件的攻击者也能重算 CRC，因此目录权限和宿主机安全仍是边界的一部分。

批次不拆分有两个理由：Kafka 失败后可以原样重放；容量和确认以条目为单位，不会留下半批状态。回放读取可合并多个条目直到记录数上限，但单个条目超过上限时仍完整返回。

## 同步与崩溃窗口

生产模式要求 `sync: true`。`tidwall/wal` 的 `NoSync=false` 会在写入完成前同步文件；只有 `Write` 成功返回，Recorder 才把批次算作已落盘。

这能覆盖进程崩溃和多数主机重启场景，但不是绝对的永久保存：磁盘损坏、文件系统故障、Volume 丢失或硬件谎报 flush 仍可能丢数据。WAL 是单节点故障缓冲，不是复制存储。

![Kafka 确认丢失与 WAL Commit 失败产生重复的时序](/ingate/images/als/lost-ack.svg)

关键故障窗口如下：

| 故障点 | 恢复结果 |
| --- | --- |
| WAL 追加前退出 | 本批没有被 ALS 确认，Envoy 可能重连，但协议不保证逐批重发 |
| WAL 同步后、返回前退出 | 条目在重启扫描中恢复，可能与 Envoy 重发形成重复 |
| Kafka 写入前退出 | 条目仍在，重启后首次投递 |
| Kafka 写入后、WAL Commit 前退出 | 重启后再次投递，ID 不变 |
| WAL Commit 成功后退出 | 条目已经删除，不再回放 |

这正是至少一次语义的来源：提交顺序偏向不丢，代价是某些窗口会重复。

## 启动恢复与损坏

队列启动时会扫描全部未确认条目，逐条验证格式版本、时间、结构、大小和 CRC。任意条目无法确认时，ALS 拒绝启动，不会自动跳过或删除。

这是一种保守选择。请求分析容忍少量丢失，不代表组件可以静默丢弃已承诺持久化的数据。运维人员应先备份整个目录，再决定离线恢复或接受数据缺口。

一个目录只允许一个进程打开。目录权限为 `0700`，锁文件和 WAL 文件为 `0600`。排他锁防止两个实例各自推进队首确认位置；它不提供网络文件系统上的分布式锁语义，因此生产部署应给每个实例独立的本地或块存储目录。

## 按物理占用控制容量

逻辑载荷只统计 protobuf 大小，不能代表真实磁盘压力。分段头、索引、锁文件、分配块取整和队首截断时的临时副本都会占用空间。ALS 读取队列目录的实际分配量，并同时检查：

- 目录占用不能超过 `capacity_bytes`；
- 文件系统必须保留 `min_free_bytes`；
- 还要留出恢复空间，至少覆盖两个配置分段或现存最大旧分段。

预留恢复空间不是为了让队列继续增长，而是保证队列接近上限时仍能复制并截断队首。没有这部分余量，最需要通过回放释放空间时，截断操作反而可能因为磁盘已满失败。

达到 80% 进入 `warning`，90% 进入 `critical`。无法容纳最小追加时进入 `blocked`。阻塞后不删除旧条目，也不改用内存队列；回放仍可运行，空间释放后自动恢复写入。
