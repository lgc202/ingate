---
title: AI 用量
description: 分析模型调用、Token 消耗和线路尝试
---

AI 用量按 Caller、Route、Service 和实际模型统计调用次数与 Token 消耗。它与实时 Token 额度相关，但使用不同的存储和查询链路。

## 统计维度

当前可以按以下维度查看调用量和 Token：

- Caller
- AI Route 与客户端模型名
- 模型 Service 与厂商实际模型
- 时间范围

页面默认查询当天。开始时间和结束时间都是必填项，单次查询不能超过 90 天。排行可以按调用次数或总 Token 排序。

输入 Token、输出 Token 和总 Token 分开保存。一次客户端请求可能因为 Route 重试产生多次模型线路尝试；请求量、模型调用次数和模型尝试次数不能混为同一个指标。

## 实时额度与用量分析

| 能力 | 存储 | 作用 |
| --- | --- | --- |
| 当前周期 Token 计数 | Redis | 在请求路径中同步判断是否允许继续调用 |
| 模型调用与 Token 事实 | ClickHouse | 查询、归属与长期聚合 |

Redis 计数追求低延迟，ClickHouse 数据追求可分析性。额度页面不能通过实时扫描请求明细计算剩余额度；用量分析也不能把 Redis 当作永久账本。

## 用量缺失

只有模型厂商返回可解析的 `usage` 时，系统才能准确记录 Token。没有 usage 的响应仍可以成功返回，但实时额度和长期 Token 统计都会缺失对应值；调用次数仍可记录。

当前不计算货币成本。不同厂商、模型、批量折扣和价格版本需要独立维护定价数据及其生效时间；现有用量数据不作为账单。
