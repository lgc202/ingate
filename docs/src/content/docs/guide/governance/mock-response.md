---
title: 模拟响应
description: 在 Route 上直接返回固定 HTTP 响应，不访问目标 Service
---

模拟响应适合维护提示、临时下线、联调占位和固定错误响应。命中策略的请求由数据面直接返回，不再访问 Route 的目标 Service。

## 前置条件

进入 **治理与扩展 → 插件**，确认“模拟响应”已经安装且状态为“已生效”。插件未安装时不能创建或更新模拟响应策略。

## 创建策略

1. 进入 **治理与扩展 → 策略**。
2. 选择 **创建策略 → 模拟响应**。
3. 选择一个或多个 Route。
4. 设置 HTTP 状态码、内容类型、响应正文和可选 Header。
5. 保存并等待策略及目标状态变为“已生效”。

状态码范围为 200–599，响应正文最大为 1 MiB。`Content-Type` 使用独立字段配置，不能在额外响应 Header 中重复填写。

策略可以不选择 Route，此时会显示“未应用”且不影响流量。一个 Route 同一时刻只能命中一条已启用的模拟响应策略；创建或更新时发现目标已被占用会返回冲突。

## 验证

例如为 `/maintenance` 所在 Route 配置状态码 `503`、内容类型 `application/json` 和正文：

```json
{"message":"service under maintenance"}
```

发送请求：

```bash
curl -i http://127.0.0.1:8080/maintenance
```

应直接收到配置的 `503`、`Content-Type`、额外 Header 和正文。目标 Service 不会收到这次请求，请求记录仍会保存最终 HTTP 结果。

## 恢复真实转发

编辑策略并关闭“启用策略”，或移除对应 Route 目标。等待新配置生效后，请求会恢复使用 Route 原有的目标 Service。卸载插件前必须先删除所有依赖它的策略；停用策略仍保留插件依赖，后端会拒绝卸载。
