title: 插件体系
description: 插件源、安装版本、强类型策略和独立升级
---

Ingate 将**插件包分发**与**网关策略配置**分开：插件页负责发现、安装、升级和卸载 Wasm 制品，策略页负责配置治理规则。

安装插件不会自动改变流量。只有对应 Policy 绑定到 Gateway 或 Route 后，Controller 才会把配置编译进 Envoy。

## 三个对象

| 对象 | 作用 | 保存位置 |
| --- | --- | --- |
| 插件源 | 提供受支持插件及版本目录 | 官方源在进程配置，自定义源是声明式资源 |
| 已安装插件 | 固定当前使用的版本、制品地址和摘要 | API Server |
| 强类型 Policy | 描述用户可理解的配置和生效目标 | API Server |

```text
插件源 → 插件市场 → 已安装版本 ─┐
                                ├→ Controller → Envoy Wasm
强类型 Policy ──────────────────┘
```

Ingate 不向用户暴露任意 JSON、Envoy Filter 名称或 Wasm ABI 字段。目录条目只有在当前控制面已经支持对应执行契约时才能安装。

## 官方源与自定义源

官方源随 Ingate 发布渠道提供。自定义源适合：

- 把官方插件镜像同步到企业内网 Registry
- 在隔离环境发布经过审计的固定版本
- 让受支持插件由不同团队维护独立发布节奏

插件页面的“插件源”标签负责添加、启停、同步和删除源。停用或删除源不会删除已经安装的插件，已安装版本仍按固定制品信息运行。

自定义源不能引入控制面未定义的 Policy 类型。新增插件能力时，Ingate 需要先提供相应的产品协议和编译适配。

## 安装与升级

每个 Release 声明：

- 插件包名和语义版本
- 最低兼容 Ingate 版本
- OCI 或 HTTP(S) 制品地址
- SHA-256 摘要

Console 根据当前 Ingate 版本选择兼容 Release。升级只修改已安装资源引用的不可变版本与摘要；Controller 成功拉取、校验并构建新配置后，才会替换当前有效版本。

插件可以独立发版，不需要跟随 Ingate 主程序版本。版本标签统一使用 `v` 前缀，例如 `v1.0.1`。

## 卸载

卸载前会检查是否仍有 Policy 依赖插件：

- 没有依赖：可以卸载，Controller 在下一次发布中移除对应 Wasm
- 存在依赖：拒绝卸载，并提示先删除或停用相关策略

依赖检查由后端执行，不依赖 Console 当前的列表数据。

## 当前插件

| 插件 | 配置入口 | 作用 |
| --- | --- | --- |
| 请求响应转换 | HeaderTransformationPolicy | 设置、追加或删除请求与响应 Header |
| 模拟响应 | MockResponsePolicy | 直接返回固定状态码、Header 和正文 |

插件市场当前只展示已支持安装、配置、生效、升级和卸载的插件。

## 新增插件要求

新增插件不仅是上传 Wasm 文件，还需要：

1. 有业务语义的强类型 Policy、Admin API 和 Console 表单
2. Controller 从 Policy 到 Envoy 配置的编译适配与冲突规则
3. Wasm 源码、构建入口和 OCI 制品发布配置
4. 包名、兼容版本、制品地址和摘要等目录元数据
5. 安装、配置、生效、升级和卸载的端到端验收

Wasm 负责数据面执行，控制面负责理解、校验和发布用户配置；两者不能只完成一半。
